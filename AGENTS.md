# Контекст проекта

- Проект: Telegram-бот на Go (Golang).
- Репозиторий: `git@github.com:mrOkk/GameParty.git`; основная ветка — `main`.
- Go-модуль: `github.com/mrOkk/GameParty`.
- Лицензия: MIT, текст находится в `LICENSE`.
- Реализация: `internal/bot`; HTTP-сервер: `cmd/server`; постоянное хранилище — Upstash Redis REST API.
- Планируемый хостинг: Vercel, тариф Hobby.
- Общение с пользователем и пояснения к изменениям — на русском языке.
- Согласованные функциональные требования первой версии находятся в `REQUIREMENTS.md`; учитывать их при реализации.

# Архитектура и разработка

- При создании приложения учитывать ограничения Vercel Hobby и совместимость выбранного способа запуска Go с платформой. Перед реализацией или настройкой деплоя проверять актуальную официальную документацию.
- Для размещения на Vercel ориентироваться на обработку Telegram updates через webhook. Не закладывать постоянный процесс или long polling без согласования изменения схемы хостинга.
- Не рассчитывать на сохранность локальной файловой системы между вызовами. Если потребуется постоянное хранение данных, отдельно выбрать подходящее хранилище.
- Токен Telegram-бота и другие секреты передавать через переменные окружения; не добавлять их в исходный код, логи и коммиты.
- Сохранять реализацию простой; добавлять зависимости и инфраструктуру только по мере необходимости.
- После изменения Go-кода выполнять форматирование и проверки, соответствующие изменению; после появления Go-модуля использовать `gofmt` и `go test ./...`.

# Коммиты

- Не добавлять `Co-authored-by` или другие подписи соавторов в сообщения коммитов.
- Сообщения коммитов должны содержать только информацию по существу внесённых изменений, без рекламных текстов, упоминаний генерации ИИ и посторонних подписей.
- Создавать коммиты только по запросу пользователя.
